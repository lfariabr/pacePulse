# v0.2.0 — Strength journey (retrospective)

Status: merged (`8707037`, PR #3), not yet tagged/released.

## What shipped

A private, server-only pipeline that turns handwritten gym-log prose into
structured strength training data, reconciled against Strava:

- `scripts/workout-extractor.sh` — extracts candidate workouts from the
  private War Room source into a gitignored `workout-review.md`, each with a
  `- [ ] Reviewed` checkbox for manual confirmation before it counts.
- `src/lib/workout-parser.ts` — parses reviewed candidates into `Workout`
  facts (date, time range, pull-ups, push-ups, conditioning efforts, focus).
- `src/lib/workout-reconciliation.ts` — matches War Room workouts against
  Strava strength (`Weight Training`) activities by timestamp/duration to
  avoid double-counting the same session from two sources.
- `src/lib/strength-ledger.ts` — combines accepted matches + unmatched
  sessions from both sources into one deduplicated `StrengthLedger`.
- `src/lib/strength-analytics.ts` — monthly totals, focus-mix percentages, a
  364-day heatmap, active days, pull-up totals, recent sessions.
- `src/app/strength/page.tsx` — new `/strength` dashboard route rendering all
  of the above, plus a "data confidence" reconciliation panel showing how many
  War Room / Strava / combined / confirmed-near-duplicate sessions make up the
  total.

Reconciled at merge time: 195 War Room workouts + 23 Strava strength records →
20 confident matches + 2 human-confirmed near-duplicates, 196 unique sessions.

## Review follow-ups (addressed same day, commit `f231800`)

CodeRabbit's automated review on PR #3 raised 6 findings; 5 were fixed
post-merge:

- **Reviewed-checkbox enforcement** — the parser was accepting every
  candidate regardless of the `- [ ] Reviewed` box, defeating the manual
  review step. Now `parseWorkoutReview` skips unticked candidates and reports
  a `not-reviewed` warning. (Required bulk-checking all 195 existing entries
  in the local, gitignored `workout-review.md` to avoid zeroing the live
  dashboard — done.)
- **Conditioning metadata bleed** — `parseConditioning` could attribute a
  wattage/distance value to the wrong effort when two conditioning efforts sat
  close together in one log line (e.g. `15 min rowing + 20 min treadmill at
  200W` assigning `200W` to both). Fixed by bounding each effort's metadata
  window to the next effort's match, not a fixed 60-character lookahead.
- **Memoized-failure reliability** — `getWorkoutDataset()` /
  `getStrengthLedger()` cached rejected promises via `??=`, so one transient
  read failure permanently broke the `force-dynamic` `/strength` page until a
  server restart. Both now clear their memoized slot on rejection so the next
  request retries.
- Two cosmetic fixes: pluralization on the "Strava-only session(s) retained"
  diagnostic label, and `currentColor` → `currentcolor` for the Stylelint
  keyword-case rule.

**Not fixed — carried forward:** possible-duplicate acceptance is currently a
single global boolean (`acceptPossibleDuplicates`) rather than a per-match
reviewer decision, so any future "possible" (non-confident) match is
auto-accepted with no individual sign-off. Low priority while Luis is the only
reviewer; worth revisiting if the ledger ever needs a second reviewer or a
larger backlog of ambiguous matches.

## Outstanding gap this roadmap builds on

`/` (Overview) and `/strength` remain fully separate pipelines — raw Strava
`Weight Training` rows still flow into Overview's cardio totals unreconciled,
which double-counts against the ledger if naively combined. This is the
starting point for [v0.3.0](0.3.0-overview-integration.md).
