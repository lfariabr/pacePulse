# v0.3.0 — Overview/strength integration

Status: shipped (`c7d842f`), not yet tagged/released.

## Goal

Let one glance at `/` show the full shape of training — cardio and strength
together — instead of requiring a trip to `/strength` to see whether lifting
is happening at all. Framed by the person who'll use it: an amateur athlete
who wants to see how their training has actually transitioned, not two
disconnected dashboards.

## Current state (why this isn't trivial)

`Activity[]` (Strava CSV, powers `/`) and `StrengthLedger` (War Room +
reconciled Strava, powers `/strength`) are two independent pipelines:

- Different types, different loaders (`csv-source.ts` vs `strength-source.ts`),
  no shared filtering.
- Raw Strava `Weight Training` rows already flow into `/`'s cardio totals as
  `sportGroup: "Strength"` — completely unreconciled against the War Room
  ledger. Naively adding the ledger on top would double-count any session that
  exists in both.
- `buildStrengthSummary` ignores `DashboardFilters` entirely — always uses the
  full dataset span, so it can't be filtered to match whatever date range is
  selected on Overview.

## Decisions locked in

- **De-duplication strategy: sum both sources, not "ledger only."** `
  StrengthLedger` already knows which Strava activity IDs got matched into a
  War Room workout (`buildStrengthLedger` in `strength-ledger.ts`). Expose
  that link and use it to build one correct merged set instead of guessing:

  ```
  mergedStrengthSessions =
    ledger.sessions
    ∪ { raw Activity rows where sportGroup === "Strength"
        AND activity.id is not already covered by ledger.sessions }
  ```

  This also fixes a bug noted in the [v0.2.0 review](0.2.0-strength-journey.md):
  Strava strength activities outside the War Room reconciliation window are
  currently silently dropped by the ledger's diagnostics. Folding them into
  Overview's merged set via the raw-activity fallback surfaces them instead of
  losing them.

- **Transition trend chart: out of scope for this release.** Considered a
  stacked monthly cardio-vs-strength bar chart to visualize the shift over
  time; deferred. This release ships the merged heatmap + metric cards only.
  Revisit the trend chart as a fast-follow once the merged data model exists.

## Implementation plan

1. **`src/lib/types.ts` + `src/lib/strength-ledger.ts`**
   Add `activityId: string | null` to `StrengthSession`, populated for
   `combined`/`strava`-sourced sessions (the underlying Strava activity ID),
   `null` for `war-room`-only sessions. This is what makes the merge in step 2
   precise instead of approximate.

2. **New merge step** (small new helper, likely `src/lib/combined-analytics.ts`)
   Build `mergedStrengthSessions` per the formula above. Single source of
   truth for all strength numbers shown on Overview.

3. **`src/lib/analytics.ts`**
   Export the window-resolution logic (`resolveWindow`, currently internal) so
   the same date-range filter Overview already supports (12m / YTD / custom /
   calendar year) applies to `mergedStrengthSessions` too — not just cardio.

4. **`src/app/page.tsx`**
   - Load `getActivityDataset()` and `getStrengthLedger()` together.
   - Exclude raw `sportGroup === "Strength"` rows from cardio-only aggregates
     (sport mix, monthly chart's existing `strengthHours` bucket) and source
     those instead from `mergedStrengthSessions`, filtered to the resolved
     window.
   - Add two new `MetricCard`s: **Strength sessions** and **Pull-ups** (the
     signature stat from `/strength`, and a more personal number than a
     generic "strength minutes" card).
   - Merge the two heatmap day-buckets (cardio `HeatmapDay[]` + strength
     `HeatmapDay[]`) into a single 52-week consistency heatmap — sum
     `movingMinutes`/`activities` per date, recompute `level`.
     `TrainingHeatmap` component needs no changes, it already takes a generic
     `HeatmapDay[]`.
   - Update the "Strength" row in the sport-mix panel to read from
     `mergedStrengthSessions` instead of raw CSV rows.

5. **Tests**
   - `strength-ledger.test.ts`: assert `activityId` is populated correctly for
     each session source.
   - New test for the merge helper: no double-counting when a session exists
     in both raw CSV and the ledger; no data loss for out-of-window Strava
     strength activities.
   - Update `page`-level expectations if there's any snapshot/integration
     coverage of the Overview metric cards or heatmap.

## What actually shipped

Implemented per plan, with two correctness bugs caught and fixed — one during
manual verification before opening the PR, one from CodeRabbit's review — and
one decision resolved:

- **Dataset-bounds bug (caught pre-PR).** Excluding raw `Strength` rows from
  the cardio dataset shifts its min/max dates inward whenever the
  newest/oldest Strava activity happened to be a weight-training entry. The
  first pass derived the strength date window from the cardio-only bounds,
  which clipped some sessions and under-counted pull-ups by 2,000 versus
  `/strength`'s figure. Fixed by widening the window to
  `min/max(cardio bounds, merged strength session bounds)` before resolving
  the filter window — verified Overview's Pull-ups card matches `/strength`
  exactly (16,345 all-time).
- **Two-clocks bug (caught by CodeRabbit review on PR #4).** The first pass
  computed the combined window in `page.tsx` but never passed it into
  `buildDashboardSummary`, which kept resolving its own window from
  cardio-only bounds internally. That meant `summary.monthly`'s zero-filled
  month range could still miss a boundary month strength data needed, and the
  merged heatmap's cardio side was built from `summary.heatmap` — which is
  `sportGroup`-filtered — while the strength side deliberately isn't,
  producing an inconsistent "half-filtered" heatmap when a sport pill was
  active. Fixed by:
  - Adding an optional `windowBounds` override to `buildDashboardSummary` so
    its internal `resolveWindow` call uses the same combined bounds computed
    in `page.tsx`, not the cardio-only ones.
  - Exporting `heatmapSeries` from `analytics.ts` and building the merged
    heatmap's cardio side directly from window-filtered (not
    `sportGroup`-filtered) cardio activities, decoupling it fully from the
    sport pill.
  - Verified: `sport=Running` now shows Running at 100% in the sport-mix panel
    while the heatmap still reports the full 325 active days, unchanged from
    the unfiltered view.
- **Also moved per CodeRabbit + `AGENTS.md`:** the merge helpers
  (`mergeStrengthSessions`, `windowStrengthSessions`, `strengthTotals`,
  `monthlyStrengthHours`, `mergedHeatmap`, `withStrengthBreakdown`) originally
  lived in a new `src/lib/combined-analytics.ts`, which violated this repo's
  own stated convention ("pure aggregation in `src/lib/analytics.ts`").
  Folded into `analytics.ts`; `combined-analytics.ts` deleted. The two new
  `MetricCard`s now route through `formatNumber` from `format.ts` instead of
  inline `.toLocaleString("en-AU")` calls, per the same file's formatting
  convention.
- **Decision resolved: `sportGroup` filter does not scope the merged heatmap
  or the two new strength cards.** They always reflect the full training
  picture for the selected date range regardless of which sport pill is
  active — matches the "whole picture" intent, and is now actually true end
  to end (see the two-clocks fix above). The monthly chart and sport-mix panel
  *do* still respect `sportGroup` (unchanged from before this release), so
  picking "Strength" there now correctly shows merged/de-duplicated numbers
  instead of raw CSV rows; picking any other single sport hides the Strength
  row from those two panels specifically.
- **Scale surprise worth knowing about:** merging in previously-invisible,
  out-of-window Strava `Weight Training` activity pushes the all-time
  "Strength sessions" count on Overview to 720 (196 reconciled War Room
  sessions + ~524 raw Strava entries from years before the War Room period
  existed) — much higher than the 196 shown on `/strength`, which only ever
  covered the reconciled window. This is intentional (no more silently
  dropped Strava-only strength history) but worth knowing before reading the
  number at a glance.

Not built: the annual "year by year" panel and personal-records panel remain
cardio-only — out of the agreed v0.3.0 scope, still open for a future pass if
wanted.
