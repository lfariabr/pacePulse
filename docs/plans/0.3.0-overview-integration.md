# v0.3.0 — Overview/strength integration

Status: planned, not started.

## Goal

Let one glance at `/` show the full shape of training — cardio and strength
together — instead of requiring a trip to `/strength` to see whether lifting
is happening at all. Framed by the person who'll use it: an amateur athlete
who wants to see how their training has actually transitioned, not two
disconnected dashboards.

## Current state (why this isn't trivial)

`Activity[]` (Strava CSV, powers `/`) and `StrengthLedger` (War Room +
reconciled Strava, powers `/strength`) are two independent pipelines:

- Different types, different loaders (`csv-source.ts` vs `strength-source.ts`),
  no shared filtering.
- Raw Strava `Weight Training` rows already flow into `/`'s cardio totals as
  `sportGroup: "Strength"` — completely unreconciled against the War Room
  ledger. Naively adding the ledger on top would double-count any session that
  exists in both.
- `buildStrengthSummary` ignores `DashboardFilters` entirely — always uses the
  full dataset span, so it can't be filtered to match whatever date range is
  selected on Overview.

## Decisions locked in

- **De-duplication strategy: sum both sources, not "ledger only."** `
  StrengthLedger` already knows which Strava activity IDs got matched into a
  War Room workout (`buildStrengthLedger` in `strength-ledger.ts`). Expose
  that link and use it to build one correct merged set instead of guessing:

  ```
  mergedStrengthSessions =
    ledger.sessions
    ∪ { raw Activity rows where sportGroup === "Strength"
        AND activity.id is not already covered by ledger.sessions }
  ```

  This also fixes a bug noted in the [v0.2.0 review](0.2.0-strength-journey.md):
  Strava strength activities outside the War Room reconciliation window are
  currently silently dropped by the ledger's diagnostics. Folding them into
  Overview's merged set via the raw-activity fallback surfaces them instead of
  losing them.

- **Transition trend chart: out of scope for this release.** Considered a
  stacked monthly cardio-vs-strength bar chart to visualize the shift over
  time; deferred. This release ships the merged heatmap + metric cards only.
  Revisit the trend chart as a fast-follow once the merged data model exists.

## Implementation plan

1. **`src/lib/types.ts` + `src/lib/strength-ledger.ts`**
   Add `activityId: string | null` to `StrengthSession`, populated for
   `combined`/`strava`-sourced sessions (the underlying Strava activity ID),
   `null` for `war-room`-only sessions. This is what makes the merge in step 2
   precise instead of approximate.

2. **New merge step** (small new helper, likely `src/lib/combined-analytics.ts`)
   Build `mergedStrengthSessions` per the formula above. Single source of
   truth for all strength numbers shown on Overview.

3. **`src/lib/analytics.ts`**
   Export the window-resolution logic (`resolveWindow`, currently internal) so
   the same date-range filter Overview already supports (12m / YTD / custom /
   calendar year) applies to `mergedStrengthSessions` too — not just cardio.

4. **`src/app/page.tsx`**
   - Load `getActivityDataset()` and `getStrengthLedger()` together.
   - Exclude raw `sportGroup === "Strength"` rows from cardio-only aggregates
     (sport mix, monthly chart's existing `strengthHours` bucket) and source
     those instead from `mergedStrengthSessions`, filtered to the resolved
     window.
   - Add two new `MetricCard`s: **Strength sessions** and **Pull-ups** (the
     signature stat from `/strength`, and a more personal number than a
     generic "strength minutes" card).
   - Merge the two heatmap day-buckets (cardio `HeatmapDay[]` + strength
     `HeatmapDay[]`) into a single 52-week consistency heatmap — sum
     `movingMinutes`/`activities` per date, recompute `level`.
     `TrainingHeatmap` component needs no changes, it already takes a generic
     `HeatmapDay[]`.
   - Update the "Strength" row in the sport-mix panel to read from
     `mergedStrengthSessions` instead of raw CSV rows.

5. **Tests**
   - `strength-ledger.test.ts`: assert `activityId` is populated correctly for
     each session source.
   - New test for the merge helper: no double-counting when a session exists
     in both raw CSV and the ledger; no data loss for out-of-window Strava
     strength activities.
   - Update `page`-level expectations if there's any snapshot/integration
     coverage of the Overview metric cards or heatmap.

## Open question to confirm before/while building

Should the merged heatmap and new strength metric cards respect the
`sportGroup` filter (e.g. hide strength entirely when filtered to "Running"),
or always show full strength context regardless of sportGroup filter since
they're meant to be the "whole picture" panel? Current lean: only apply the
date-range filter, not sportGroup, to the merged/strength-specific panels —
sportGroup filtering stays scoped to the existing cardio-focused
monthly-chart/sport-mix sections. Flag if that reads wrong once built.
